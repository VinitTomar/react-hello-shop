# v0.11 — Performance Optimization

### Product Requirement Specification

---

## 1. Overview

**Goal:** Add a sort control to the Home page, then apply `React.memo`, `useMemo`, and `useCallback` to eliminate the unnecessary re-renders the new state produces. Profile with React DevTools Profiler before and after to make the improvement measurable and visible.

**End result:** The Home page gains a "Sort by" dropdown. Changing the sort order re-renders only the components that genuinely need to update — `SortBar` does not re-render when its props haven't changed; individual `ProductCard` instances are skipped when their underlying `product` reference is identical to the previous render. The React DevTools flame graph shows the difference: a sort change produces 6 `ProductCard` renders without `memo`, and 0 `ProductCard` renders with `memo` (React reconciles by `key`, moves DOM nodes, and skips component render entirely when props are equal).

**Why this comes after v0.9:** The optimization targets a data-driven component tree. `useMemo` is meaningful when there is real derived state — sorting an async-loaded product array. `React.memo` is meaningful when a parent re-renders frequently enough to cause wasted child renders. v0.9 establishes the async data layer; v0.11 adds local controlled state on top of it, creating the re-render pressure worth measuring.

## 2. Background & Constraints

### Starting Point (v0.9 is complete)

| What's ready | Notes |

| `src/types/product.ts` | `Product` interface with `id: number` — unchanged |

### Module Constraints

- **No new package installs.** `React.memo`, `useMemo`, and `useCallback` are built into React.
- **`memo` uses `Object.is` for prop comparison.** Primitive props compare by value. Object/array/function props compare by reference. TanStack Query preserves individual `Product` object references when cached data has not changed — the same product is the same reference across re-renders within the `staleTime` window.
- **`[...products].sort()` is required.** `Array.sort()` mutates the array in place. The `useMemo` derivation must spread before sorting — mutating TanStack Query's cached array would corrupt the cache entry.
- **React reconciles `ProductCard` by `key={p.id}`.** `ProductGrid` already uses `key={p.id}`. When the sort order changes, React reconciles each card to its product ID key — it moves DOM nodes to reflect the new order, then checks `memo`'s prop comparison per card. Because TanStack Query returns the same `Product` object references (unchanged cached data), every card's `product` prop passes `Object.is` equality. Result: a sort change produces **zero** `ProductCard` re-renders with `memo` in place.
- **`SortBar` is a leaf component.** It receives `sortBy` and `onSortChange` as props. Wrapping it in `memo` means it only re-renders when those props change. `useCallback` on `handleSortChange` stabilizes the function reference — without it, a new function object on every `Home` render would break `memo`'s equality check on the callback prop.
- **React DevTools Profiler extension is required.** The browser extension must be installed before starting. Recording a baseline before adding `memo` is essential — once the optimization is applied, the before-state is gone.
- **6 products means no measurable latency gain.** The value is pattern recognition and tooling fluency, not runtime benchmarks. Profile to understand the render graph.

This pattern matters in production apps where parent re-renders are frequent and outside your control.

## 5. Shared Patterns

### `SortKey` type

Defined in `src/types/sort.ts`, imported by both `Home.tsx` and `SortBar.tsx`. A union of the three valid sort identifiers.

```ts
export type SortKey = "name" | "price_asc" | "price_desc";
```

### `memo` export pattern

Used in both `ProductCard` and `SortBar`. The inner function is named — React DevTools uses the function name for the flame graph label. An anonymous arrow function wrapped in `memo` would appear as `memo(Component)` in the flame graph; a named function appears as `ProductCard` or `SortBar`.

```tsx
// Named inner function — DevTools label is "ProductCard"
function ProductCard(props: ProductCardProps) { ... }

// memo wraps the named function and becomes the module's default export
export default memo(ProductCard);
```

### 6.2 `src/components/SortBar.tsx` — NEW

**Wireframe:**

```
┌────────────────────────────────────────────────────────┐
│  Sort by: [Name              ▼]                        │
│            Name                                        │
│            Price: Low → High                           │
│            Price: High → Low                           │
└────────────────────────────────────────────────────────┘
← flex items-center gap-2 mb-6
```

**CSS classes:**

| Element | Classes |
| --- | --- |
| Container `<div>` | `flex items-center gap-2 mb-6` |
| Label `<span>` | `text-sm text-gray-500` |
| `<select>` | `text-sm border border-gray-200 rounded-md px-2 py-1 text-gray-700 bg-white focus:outline-none focus:ring-2 focus:ring-blue-500` |

**Requirements:**
- Import `memo` from `"react"`
- Import `SortKey` from `@/types/sort`
- Define `SortBarProps`: `{ sortBy: SortKey; onSortChange: (sort: SortKey) => void }`
- `SORT_OPTIONS` is a **module-level constant** array — not defined inside the component body
- `onChange` handler casts `e.target.value` to `SortKey` — the cast is safe because the `<option>` values are exclusively `SortKey` members
- Default export: `memo(SortBar)` — inner function named `SortBar`

```tsx
import { memo } from "react";
import type { SortKey } from "@/types/sort";

interface SortBarProps {
  sortBy: SortKey;
  onSortChange: (sort: SortKey) => void;
}

const SORT_OPTIONS: { value: SortKey; label: string }[] = [
  { value: "name", label: "Name" },
  { value: "price_asc", label: "Price: Low → High" },
  { value: "price_desc", label: "Price: High → Low" },
];

function SortBar({ sortBy, onSortChange }: SortBarProps) {
  return (
    <div className="flex items-center gap-2 mb-6">
      <span className="text-sm text-gray-500">Sort by:</span>
      <select
        value={sortBy}
        onChange={(e) => onSortChange(e.target.value as SortKey)}
        className="text-sm border border-gray-200 rounded-md px-2 py-1 text-gray-700 bg-white focus:outline-none focus:ring-2 focus:ring-blue-500"
      >
        {SORT_OPTIONS.map((opt) => (
          <option key={opt.value} value={opt.value}>
            {opt.label}
          </option>
        ))}
      </select>
    </div>
  );
}

export default memo(SortBar);
```

> **`SORT_OPTIONS` is module-level.** Defining it inside the component body would create a new array reference on every render. `memo`'s shallow comparison wouldn't see `SORT_OPTIONS` as a prop here (it's not passed in), but this is the general rule: any constant that does not depend on props or state belongs outside the component — arrays, maps, and pure functions alike.

> **`e.target.value as SortKey`:** TypeScript types `e.target.value` as `string`. The `as SortKey` cast is safe because the `<select>` element only ever holds values from `SORT_OPTIONS`, which are exhaustively typed as `SortKey` members. No runtime validation is needed.

### 6.3 `src/components/ProductCard.tsx` — UPDATED

**No visual change.** The only difference from v0.9 is the default export.

**Requirements:**
- Add `memo` to the React import: `import { memo } from "react"`
- Keep all existing logic, props, and JSX unchanged
- Change the default export from `export default ProductCard` to `export default memo(ProductCard)`
- The inner function declaration `function ProductCard(...)` must stay named — React DevTools shows this name in the flame graph

```tsx
import { memo } from "react";
import type { Product, ProductCardVariant } from "@/types/product";

export type ProductCardProps = { product: Product } & ProductCardVariant;

const categoryBadgeClasses: Record<string, string> = {
  Electronics: "bg-blue-100 text-blue-700",
  Clothing: "bg-purple-100 text-purple-700",
  Books: "bg-amber-100 text-amber-700",
};

function ProductCard({
  product: { imageUrl, name, price, category, description },
  variant,
}: ProductCardProps) {
  return (
    <div className="bg-white rounded-xl shadow-sm border border-gray-100 hover:shadow-lg hover:-translate-y-1 transition-all duration-200">
      <img
        src={imageUrl}
        alt={name}
        loading="lazy"
        className="w-full aspect-[4/3] object-cover rounded-t-xl"
      />
      <div className="p-4 flex flex-col">
        {variant === "full" && (
          <span
            className={
              (categoryBadgeClasses[category] ?? "bg-gray-100 text-gray-700") +
              " self-start text-xs font-medium px-2 py-0.5 rounded-full mb-2"
            }
          >
            {category}
          </span>
        )}
        <span className="text-sm font-semibold text-gray-900">{name}</span>
        <span className="text-base font-bold text-gray-900">
          ${price.toFixed(2)}
        </span>
        {variant === "full" && (
          <span className="text-sm text-gray-500">{description}</span>
        )}
      </div>
    </div>
  );
}

export default memo(ProductCard);
```

> **Why `memo` on `ProductCard`?** `ProductGrid` renders all cards when its `products` prop changes (which happens on every sort change — `useMemo` produces a new array). Without `memo`, React re-renders each card unconditionally. With `memo`, React compares each card's `product` prop via `Object.is`. Because TanStack Query returns the same `Product` object references (unchanged cached data), the comparison passes for all 6 cards and React skips rendering their subtrees entirely. The observable result: zero `ProductCard` renders in the Profiler after a sort change, despite `ProductGrid` receiving a new array.

**`sortProducts` function (module-level):**

```ts
function sortProducts(products: Product[], sortBy: SortKey): Product[] {
  return [...products].sort((a, b) => {
    if (sortBy === "name") return a.name.localeCompare(b.name);
    if (sortBy === "price_asc") return a.price - b.price;
    return b.price - a.price;
  });
}
```

**Full component:**

```tsx
import { useCallback, useMemo, useState } from "react";
import { useQuery } from "@tanstack/react-query";
import { fetchProducts } from "@/api/products";
import ProductGrid from "@/components/ProductGrid";
import SortBar from "@/components/SortBar";
import type { SortKey } from "@/types/sort";
import type { Product } from "@/types/product";

function sortProducts(products: Product[], sortBy: SortKey): Product[] {
  return [...products].sort((a, b) => {
    if (sortBy === "name") return a.name.localeCompare(b.name);
    if (sortBy === "price_asc") return a.price - b.price;
    return b.price - a.price;
  });
}

export default function Home() {
  const [sortBy, setSortBy] = useState<SortKey>("name");

  const { data: products, isPending, isError } = useQuery({
    queryKey: ["products"],
    queryFn: fetchProducts,
  });

  const sortedProducts = useMemo(
    () => (products ? sortProducts(products, sortBy) : []),
    [products, sortBy],
  );

  const handleSortChange = useCallback((sort: SortKey) => {
    setSortBy(sort);
  }, []);

  if (isPending) {
    return (
      <div className="max-w-7xl mx-auto px-4 py-8">
        <p className="text-gray-500">Loading products…</p>
      </div>
    );
  }

  if (isError) {
    return (
      <div className="max-w-7xl mx-auto px-4 py-8">
        <p className="text-gray-500">Failed to load products.</p>
      </div>
    );
  }

  return (
    <div className="max-w-7xl mx-auto px-4 py-8">
      <SortBar sortBy={sortBy} onSortChange={handleSortChange} />
      <ProductGrid products={sortedProducts} />
    </div>
  );
}
```

> **`[...products].sort()`:** `Array.sort()` mutates in place. Spreading creates a new array for sorting, leaving TanStack Query's cached `products` reference intact. Mutating the cached array would corrupt subsequent reads from the cache.

> **`products ?` guard in `useMemo`:** `products` is `undefined` while the query is loading. `useMemo` runs on every render — including the initial render before the early return for `isPending`. The guard prevents passing `undefined` to `sortProducts`. An empty array is returned in that case, which is never passed to `<ProductGrid>` (the early return fires first).

> **Module-level `sortProducts`:** Defining it inside the component body would create a new function reference on every render. `useMemo`'s correctness depends on its dependency array, not on whether `sortProducts` is stable, so this is not a correctness concern — it is an idiomatic clarity concern. Pure functions with no closure over component state belong at module level.

> **`useCallback` with `[]`:** `handleSortChange` wraps `setSortBy`, which is already a stable reference from `useState`. The explicit `useCallback` wrapper is shown for the pattern — in real code, the callback usually closes over `id`, `userId`, or other state variables that change, making `useCallback` genuinely necessary. Recognizing the pairing of `memo(SortBar)` + `useCallback` is the learning outcome.

## 8. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| `React.memo` | `ProductCard.tsx`, `SortBar.tsx` | Wraps a component; React skips rendering if every prop passes `Object.is` comparison — the component and its subtree are not re-evaluated |
| Named function + `memo(name)` export | Both | The inner function name is the DevTools flame graph label — wrapping an anonymous arrow would show `memo(Component)` instead of the readable component name |
| `Object.is` prop comparison | `ProductCard.tsx` | Primitives compare by value; objects/arrays/functions by reference — stable references from `useQuery` make `memo` on data-display components effective |
| `key` reconciliation + `memo` | `ProductGrid.tsx` + `ProductCard.tsx` | React matches components to their `key` across renders; when sort reorders the array, React moves DOM nodes by key, then calls `memo`'s comparator per card — with stable product references, all 6 cards skip rendering |
| `useMemo(fn, deps)` | `Home.tsx` | Memoizes the return value; re-runs `fn` only when a dependency changes; `[...products].sort()` runs once per data/sort change, not on every render |
| `[...arr].sort()` spread before sort | `Home.tsx` | `Array.sort()` is mutating; spreading creates a new array for the sorted result and leaves TanStack Query's cached array unmodified |
| `useCallback(fn, deps)` | `Home.tsx` | Memoizes the function reference; essential when the function is a prop to a `memo`-wrapped child — a new reference on every render breaks `memo`'s equality check for that prop |
| `memo` + `useCallback` pairing | `Home.tsx` → `SortBar.tsx` | `memo(SortBar)` is ineffective if `onSortChange` is recreated every render; the two are always co-dependent when passing callbacks to memoized children |
| Module-level constants and functions | `SortBar.tsx` (`SORT_OPTIONS`), `Home.tsx` (`sortProducts`) | Arrays and pure functions defined outside the component body are created once at module load — not on every render |
| Profiler flame graph reading | React DevTools | Gray = no render; colored = rendered; width ≈ render duration; hover a bar for "why did this render?" — shows which prop changed |
| "Highlight updates" overlay | React DevTools | Real-time per-component flash on DOM updates — the fastest way to spot unexpected re-renders without recording a full Profiler session |
| When NOT to memoize | All | `memo` adds a comparison cost on every render; `useMemo`/`useCallback` add memory overhead. Only apply after the Profiler identifies a measurable problem. Premature memoization obscures code for no gain. |
