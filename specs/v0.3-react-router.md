# v0.3 — React Router v6

### Product Requirement Specification

---

## 1. Overview

**Goal:** Convert Hello Shop from a single-page render into a real multi-route application using React Router v6. Add four page-level components (Home, ProductDetail, Cart, NotFound), wire all internal navigation through `<Link>`, and enable click-through from the product grid to a dedicated detail page.

**End result:** Clicking any product card navigates to `/products/:id` and shows the product's full details. The Header "Home" and "Cart" links navigate without triggering a full page reload. Entering an unknown URL shows a friendly 404 page. The app behaves like a real web app — the browser back button works, URLs are shareable, and no white-flash reloads occur on navigation.

**Why this comes after v0.2:** Routing is a wrapper around components — typed components must be defined before they can be assigned to routes. Also, `useParams` is only meaningful once a `Product` interface exists to look up against. v0.3 deliberately keeps data in a static module (no API, no state) so the learning focus stays on URL-driven rendering, not data fetching.

### Module Constraints

- **No cart state.** The Cart page shows a static empty-state message only. Cart interactions are wired in v0.6 (Zustand).
- **No API calls.** `MOCK_PRODUCTS` moves from `App.tsx` to `src/data/products.ts` so both `Home` and `ProductDetail` can import it without prop drilling through the route tree.
- **Router variant: classic JSX routes.** Use `<BrowserRouter>` in `main.tsx` and `<Routes>`/`<Route>` in `App.tsx`. Do not use `createBrowserRouter` — that API (v6.4+) adds loader/action complexity before the routing fundamentals are clear.
- **ProductCard unchanged.** Clickability belongs to the grid layer: `ProductGrid` wraps each `<li>` in a `<Link>`. `ProductCard` itself stays routing-agnostic and can be reused in non-navigable contexts.
- **Tailwind only.** No inline styles, no CSS modules.
- **React 19 JSX transform.** `import React from 'react'` is not needed.

### Out of Scope (do not build in this module)

| Feature                           | Planned for |
| --------------------------------- | ----------- |
| Cart add / remove / quantity      | v0.6        |
| Category filtering / search bar   | v0.4        |
| Nested layouts with `<Outlet>`    | future      |
| Loading skeletons                 | v0.9        |
| Dark mode                         | v0.7        |
| Active link styling via `NavLink` | v0.7        |

## 8. Concepts Learned

| Concept                       | Where it appears                | Why it matters                                                                                      |
| ----------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------- |
| `BrowserRouter`               | `main.tsx`                      | Provides router context to the entire component tree — must be an ancestor of every `<Link>` / hook |
| `Routes` + `Route`            | `App.tsx`                       | Declarative route config — React Router renders the element whose path matches the current URL      |
| `Link` vs `<a>`               | `Header.tsx`, `ProductGrid.tsx` | `<Link>` pushes a new history entry via the History API; `<a>` triggers a full HTTP request         |
| `useParams`                   | `ProductDetail.tsx`             | Reads dynamic URL segments (`:id`) as a typed object — the primary way to access route data         |
| `useNavigate`                 | `ProductDetail.tsx`             | Programmatic navigation — back buttons, post-action redirects, and guarded routes                   |
| Wildcard `*` route            | `App.tsx`                       | Catch-all: matches everything not matched above — essential for graceful 404 handling               |
| Pages vs Components directory | Entire app                      | Pages are route-level entry points (one per URL); components are reusable building blocks           |
| Data module separation        | `src/data/products.ts`          | Shared data moved out of `App.tsx` — avoids prop drilling and prepares the shape for v0.9 (API)     |
| TypeScript generic params     | `useParams<{ id: string }>()`   | React Router's hooks accept generic type arguments — the returned object is typed, not `any`        |
| Inline not-found guard        | `ProductDetail.tsx`             | A valid-looking URL with a bad ID is not a 404 — handle it inline, not with a redirect              |
