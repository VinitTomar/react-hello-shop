# v0.2 — Component Architecture
### Product Requirement Specification

---

## 1. Overview

**Goal:** Establish the core UI building blocks of Hello Shop — a sticky page header and a responsive product grid — using React component composition and TypeScript's type system.

**End result:** A full-page layout with a header fixed at the top and a grid of 6 product cards below, all populated from a hardcoded in-memory data array. No interactions, no navigation, no data fetching — purely static structure.

**Why this comes first:** Typed components are the foundation. You cannot wire components to routes (v0.3), state stores (v0.6), or an API (v0.9) until you have defined their props and data shapes. This module is intentionally stateless so the learning focus stays entirely on TypeScript patterns and component design.

## 2. Background & Constraints

### Starting Point (v0.1 is complete)

| What's ready | Notes |
|---|---|
| React 19 + TypeScript 6, strict mode on | All strict checks active |
| Tailwind CSS v4 via `@tailwindcss/vite` | No `tailwind.config.js`, no PostCSS — utility class names are the same as v3, only configuration differs |
| `@/` path alias → `src/` | Wired in both `vite.config.ts` and `tsconfig.app.json` |
| ESLint + Prettier | Already configured |

### Module Constraints

- **No routing.** Everything renders inside a single `App.tsx`. Nav links are `<a href="#">` placeholders; real routing arrives in v0.3.
- **No state.** No `useState`, no context, no store of any kind.
- **No API calls.** Product data is a hardcoded constant defined in `App.tsx`.
- **Tailwind only.** All styling via utility classes. No inline styles, no CSS modules.
- **React 19 JSX transform.** You do not need `import React from 'react'` at the top of component files. Many tutorials still show this import — ignore it.

### Out of Scope (do not build in this module)

| Feature | Planned for |
|---|---|
| Dark mode toggle | v0.7 |
| Category filtering / search bar | v0.4 |
| "Add to cart" button or cart state | v0.6 |
| Sorting | v0.4 |
| Click-through to product detail | v0.3 |
| Loading skeletons / spinners | v0.9 |
| Pagination or infinite scroll | v0.10 |

## 3. Folder Structure to Produce

```
src/
├── types/
│   └── product.ts          ← Product interface + variant union
├── components/
│   ├── Header.tsx          ← static page header
│   ├── ProductCard.tsx     ← single product card, two display variants
│   └── ProductGrid.tsx     ← lays out a list of ProductCards
├── App.tsx                 ← composes Header + ProductGrid with mock data
├── index.css               ← unchanged
└── main.tsx                ← unchanged
```

**File & export conventions:**
- One component per file. Filename matches component name exactly (PascalCase).
- **Components:** default export.
- **Types and interfaces:** named export. `types/product.ts` has no React imports — it is pure TypeScript.

## 5. File Specifications

### `src/types/product.ts`

The single source of truth for data shapes used across all components.

| Export | Kind | Fields / Members |
|---|---|---|
| `Product` | `interface` | `id: number`, `name: string`, `price: number` (raw USD value, no symbol), `imageUrl: string`, `category: string`, `description: string` |
| `ProductCardVariant` | discriminated union type | `{ variant: 'compact' }` \| `{ variant: 'full' }` — the `variant` field is the discriminant TypeScript uses to narrow |

---

### `src/components/Header.tsx`

The persistent top bar visible on every page.

**Props:** none (static for this module)

**Layout:**
- Full-width horizontal bar
- Left side: store logo / name ("Hello Shop")
- Right side: two nav links — `Home` and `Cart`

**Behaviour:**
- Nav links are plain `<a href="#">` — they look like links but navigate nowhere. Real `<Link>` components arrive in v0.3.
- Header sticks to the top of the viewport on scroll (`sticky top-0`).
- Background must be fully opaque so content scrolling beneath it is hidden.

**Semantic HTML requirements:**
- Root element: `<header>`
- Nav links wrapped in: `<nav>`

---

### `src/components/ProductCard.tsx`

Displays a single product. Supports two visual densities controlled by a discriminated union prop.

**Props:** `product: Product` + spread of `ProductCardVariant` (so the component receives both `product` and `variant` as top-level props)

#### `compact` variant — used by the grid

| Element | Detail |
|---|---|
| Image | Full card width, fixed 4:3 aspect ratio |
| Name | Product name |
| Price | Formatted as `$XX.XX` — always two decimal places |
| Category | Not shown |
| Description | Not shown |

#### `full` variant — reserved for future detail contexts

Includes everything in `compact`, plus:

| Element | Detail |
|---|---|
| Category | Rendered as a small pill / badge |
| Description | Full description text |

**TypeScript requirement:** Use a discriminated union narrowing check (`if (variant === 'full')`) to conditionally render the extra fields. TypeScript must statically guarantee the `full` branch is unreachable when `variant === 'compact'`. No type assertions (`as`), no `any`.

**Visual states:**
- Default: card with subtle border / shadow
- Hover: card lifts slightly (`hover:shadow-lg hover:-translate-y-1 transition`) to hint at future clickability

**Image handling:**
- Source URL: `https://picsum.photos/seed/{product.id}/400/300` — deterministic placeholder, no account needed. This URL is stored in `product.imageUrl`.
- `alt` attribute: must be `{product.name}` — never empty, never `"image"`.
- Include `loading="lazy"` on the `<img>` tag.

**Interactions:** No click handler. Clicking a card does nothing in this module.

---

### `src/components/ProductGrid.tsx`

Lays out a collection of `ProductCard` components in a responsive grid.

**Props:** `products: Product[]`

**Layout:** CSS grid
- Mobile: 1 column
- `sm` breakpoint: 2 columns
- `lg` breakpoint: 3 columns

**Rendering:**
- Each product renders as `<ProductCard variant="compact" product={p} />` with `key={p.id}`.
- The `compact` variant is hardcoded inside `ProductGrid`. The component does **not** accept a `variant` prop — the grid is always a compact listing. The `full` variant is a concern for a detail page (v0.3).

**Empty state:**
- When `products.length === 0`, render a centred "No products found." message.
- This is a **separate render path** (an early return or conditional block), not a hidden element toggled by CSS.

**Semantic HTML:** Use `<ul>` as the grid container, `<li>` wrapping each card.

---

### `src/App.tsx` (updated)

The root composition layer. Contains mock data and assembles the page.

**Mock data — `MOCK_PRODUCTS` constant:**

Category strings must be title case exactly as shown. v0.4 will run filter comparisons against these strings.

| id | name | category | price |
|---|---|---|---|
| 1 | Wireless Headphones | Electronics | 79.99 |
| 2 | Running Shoes | Clothing | 59.99 |
| 3 | TypeScript Handbook | Books | 29.99 |
| 4 | Mechanical Keyboard | Electronics | 149.99 |
| 5 | Denim Jacket | Clothing | 89.99 |
| 6 | React Deep Dive | Books | 9.99 |

Each product also needs a short one-sentence `description` and an `imageUrl` following the picsum pattern above.

**Page structure:**
```
<Header />
<main>                    ← max-width container, centred, horizontal padding
  <ProductGrid products={MOCK_PRODUCTS} />
</main>
```

The `<main>` element must have a max-width and horizontal padding so the grid does not span edge-to-edge on large screens (e.g. `max-w-7xl mx-auto px-4`).

**No state, no effects** — `App.tsx` is pure composition.

## 7. Concepts Learned

| Concept | Where it appears | Why it matters |
|---|---|---|
| TypeScript `interface` | `src/types/product.ts` | Defines the shape of data flowing through the whole app |
| Discriminated union | `src/types/product.ts` + `ProductCard.tsx` | TypeScript narrows a union using a literal field — the compiler enforces which branch runs |
| Typed component props | Every component | Without typed props, passing wrong data is a runtime error, not a compile error |
| Default vs named exports | Types: named; components: default | Makes imports predictable and consistent across the codebase |
| Component composition | `App.tsx` | React apps are trees of components — not monolithic files |
| Conditional rendering via type narrowing | `ProductCard.tsx` | TypeScript statically proves the `full` branch is only reachable when `variant === 'full'` |
| Props drilling | `App.tsx` → `ProductGrid` → `ProductCard` | Understand how data flows through a component tree before introducing a state manager |
| `Array.map()` + `key` prop | `ProductGrid.tsx` | React uses `key` to efficiently reconcile list changes — it must be stable and unique per item |
| Empty state as a separate render path | `ProductGrid.tsx` | UI should always handle the zero-items case explicitly, not silently show a blank screen |
| Semantic HTML | `Header.tsx`, `ProductGrid.tsx` | Screen readers and search engines use landmark elements (`<header>`, `<nav>`, `<ul>`) |
