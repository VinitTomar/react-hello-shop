# v0.6 — Zustand

### Product Requirement Specification

---

## 1. Overview

**Goal:** Implement a fully-functional cart using Zustand as the client state store. Wire up the "Add to Cart" button on `ProductCard` and `ProductDetail`, add a live item-count badge to the Header, and transform the static Cart page from v0.3 into a real cart UI with quantity controls, per-item remove, a running total, and a "Clear Cart" action.

**End result:** Clicking "Add to Cart" on any product card (or on the detail page) adds it to the Zustand store. The Header badge updates immediately to show the total item count. The `/cart` route lists every item with `−`/`+` quantity controls, a unit remove button, a grand total, and a "Clear Cart" button. Navigating away and back — or refreshing the page — preserves cart state because the store is persisted to `localStorage` via Zustand's `persist` middleware.

**Why this comes after v0.4/v0.5:** v0.4 (forms) and v0.5 (custom hooks) are independent of the cart feature. v0.6 deliberately keeps data local (no API) so the learning focus stays on the Zustand store shape, derived selectors, and middleware — not on async state.

## 4. Type Definitions

Defined and exported from `src/store/cartStore.ts`.

```ts
export interface CartItem {
  product: Product;
  quantity: number;
}

export interface CartStore {
  items: CartItem[];
  addToCart: (product: Product) => void;
  removeFromCart: (productId: number) => void;
  updateQuantity: (productId: number, quantity: number) => void;
  clearCart: () => void;
}
```

**Design notes:**
- `CartItem` embeds the full `Product` object (not just the ID) so cart display components can render name, price, and `imageUrl` without a secondary lookup.
- `updateQuantity` takes an absolute `quantity` value; increment/decrement arithmetic is a UI concern and belongs at the call site.
- Derived values (`totalItems`, `totalPrice`) are **not** stored — they are computed inline via Zustand selectors in the components that need them.

### 6.1 `src/store/cartStore.ts` — NEW

**Requirements:**
- Install: `pnpm add zustand`
- Import `create` from `zustand`; import `persist` and `devtools` from `zustand/middleware`
- Import `Product` from `@/types/product`
- Export `CartItem` and `CartStore` interfaces (see Section 4)
- Export `useCartStore` hook

**Middleware composition:** `devtools` wraps `persist` — this is the correct ordering so Redux DevTools shows persisted state correctly.

```ts
import { create } from 'zustand'
import { devtools, persist } from 'zustand/middleware'
import type { Product } from '@/types/product'

export interface CartItem {
  product: Product;
  quantity: number;
}

export interface CartStore {
  items: CartItem[];
  addToCart: (product: Product) => void;
  removeFromCart: (productId: number) => void;
  updateQuantity: (productId: number, quantity: number) => void;
  clearCart: () => void;
}

export const useCartStore = create<CartStore>()(
  devtools(
    persist(
      (set) => ({
        items: [],
        addToCart: (product) =>
          set((state) => {
            const existing = state.items.find(
              (item) => item.product.id === product.id
            );
            if (existing) {
              return {
                items: state.items.map((item) =>
                  item.product.id === product.id
                    ? { ...item, quantity: item.quantity + 1 }
                    : item
                ),
              };
            }
            return { items: [...state.items, { product, quantity: 1 }] };
          }),
        removeFromCart: (productId) =>
          set((state) => ({
            items: state.items.filter((item) => item.product.id !== productId),
          })),
        updateQuantity: (productId, quantity) =>
          set((state) => ({
            items: state.items.map((item) =>
              item.product.id === productId ? { ...item, quantity } : item
            ),
          })),
        clearCart: () => set({ items: [] }),
      }),
      { name: 'cart-storage' }
    )
  )
);
```

**Note on `updateQuantity`:** The store does not guard against `quantity ≤ 0`. The Cart page UI prevents reaching 0 by disabling the `−` button at `quantity === 1` — the store stays simple.

## 8. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| `create<T>()()` double call | `cartStore.ts` | The curried factory enables full TypeScript inference when middleware is composed — `create<T>()(middleware(...))` is idiomatic Zustand v4+ |
| `set` updater function | All store actions | Receives current state and returns a partial next state — same mental model as functional `setState` |
| Immutable array updates | `addToCart`, `updateQuantity` | Zustand uses shallow equality; mutating arrays in place bypasses re-renders — always return new arrays via `map`/`filter`/spread |
| Zustand selector | `Header.tsx`, `Cart.tsx`, `ProductDetail.tsx` | `useCartStore(state => state.x)` subscribes only to `x` — prevents unrelated re-renders when other parts of the store change |
| Derived values via selector | `totalItems` (Header), `totalPrice` (Cart) | Computed values don't need to live in the store — compute them in the selector to keep the store minimal |
| `persist` middleware | `cartStore.ts` | Serialises store state to `localStorage` automatically; the `name` key is the storage key used by the browser |
| `devtools` middleware | `cartStore.ts` | Exposes the store to Redux DevTools browser extension — time-travel debugging works without Redux |
| Middleware composition order | `devtools(persist(...))` | Zustand middlewares compose from inside out — `persist` handles serialisation first, then `devtools` wraps it for visibility |
| `e.stopPropagation()` | `ProductCard.tsx` button | Prevents the click event bubbling up to the parent `<Link>` in ProductGrid, which would trigger navigation instead of adding to cart |
