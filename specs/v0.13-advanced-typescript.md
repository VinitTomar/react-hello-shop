# v0.13 — Advanced TypeScript Patterns

### Product Requirement Specification

---

## 1. Overview

**Goal:** Build a `SortableTable<T>` generic component that renders tabular data with clickable-header sort, then use it to replace the card list on the Orders page. Across two new files — `src/types/table.ts` and `src/components/SortableTable.tsx` — demonstrate five TypeScript patterns: generic components, mapped types, conditional types, template literal types, and the `satisfies` operator. Each pattern appears in working application code, not in isolation.

**End result:** Visiting `/orders` shows a responsive table with five columns — Order #, Date, Status, Items, Total — instead of the card list from v0.8. Clicking any sortable column header re-orders rows; the active column shows a `↑` or `↓` indicator. `SortableTable` is fully generic: a wrong `sortKey` (e.g., `sortKey: 'items'`) or a mismatched row type is caught at compile time. The runtime behaviour is unchanged — the same three mock orders load after the same 800 ms skeleton.

**Why this comes after v0.12:** v0.11 and v0.12 are runtime concerns (render performance, bundle size). v0.13 is a compile-time concern — it adds no new runtime features beyond v0.8, but makes the Orders feature dramatically more type-safe. Placing it here means every prior concept (routes, state, server state, lazy loading) is complete; the TypeScript abstraction is being layered on top of a fully working app.

## 4. TypeScript Patterns Reference

| Pattern | Syntax | File | Role in this module |
| --- | --- | --- | --- |
| Generic component | `function SortableTable<T>(props: SortableTableProps<T>)` | `SortableTable.tsx` | Row type `T` flows through to column definitions, sort state, and the sort comparator |
| Mapped type | `{ [K in keyof T]: T[K] extends ... ? K : never }[keyof T]` | `types/table.ts` | Derives `SortableKeys<T>` — the union of T's keys whose values are primitive |
| Conditional type | `T[K] extends string \| number \| boolean ? K : never` | `types/table.ts` | Inside the mapped type — keys with array or object values map to `never` and fall out of the union |
| Template literal type | `` `${string & SortableKeys<T>}_${SortDirection}` `` | `types/table.ts` | Produces `TableSortKey<T>` — every valid `"field_direction"` string for type `T`; used as the type of `SortableTableProps<T>.defaultSort` |
| `satisfies` operator | `ORDER_COLUMNS = [...] satisfies ColumnDef<Order>[]` | `Orders.tsx` | Validates each column object against `ColumnDef<Order>` while preserving literal types for inference |

**`SortableKeys<Order>` — traced:**

```
Order = { id: string; createdAt: string; status: OrderStatus; items: OrderItem[]; total: number }

  id        → string extends string | number | boolean  → true  → 'id'
  createdAt → string extends ...                        → true  → 'createdAt'
  status    → OrderStatus (= 'processing' | 'shipped' | 'delivered') extends string → true → 'status'
  items     → OrderItem[] extends ...                   → false → never
  total     → number extends ...                        → true  → 'total'

SortableKeys<Order> = 'id' | 'createdAt' | 'status' | 'total'
```

**`TableSortKey<Order>` — traced:**

```
`${string & ('id' | 'createdAt' | 'status' | 'total')}_${'asc' | 'desc'}`

= 'id_asc' | 'id_desc' | 'createdAt_asc' | 'createdAt_desc'
  | 'status_asc' | 'status_desc' | 'total_asc' | 'total_desc'
```

### 6.1 `src/types/table.ts` — NEW

**Requirements:**
- Type-only import: `import type { ReactNode } from 'react'`
- Named exports only — no default export, no React component, no JSX

```typescript
import type { ReactNode } from 'react'

// Two-value union for sort direction — interpolated into TableSortKey<T>
export type SortDirection = 'asc' | 'desc'

// Mapped + conditional type: keys of T whose values are string | number | boolean
// Array and object fields map to `never` and fall out of the union
export type SortableKeys<T> = {
  [K in keyof T]: T[K] extends string | number | boolean ? K : never
}[keyof T]

// Template literal type: every valid "field_direction" string for T
// `string &` narrows keyof T to string-only keys — keyof T can include symbols,
// which are not valid template literal interpolants
// Named TableSortKey (not SortKey) to avoid colliding with the unrelated,
// non-generic SortKey exported from @/types/sort (product list sorting).
// Used as the type of SortableTableProps<T>.defaultSort below.
export type TableSortKey<T> = `${string & SortableKeys<T>}_${SortDirection}`

// Current sort state stored inside SortableTable
export interface SortState<T> {
  key: SortableKeys<T>
  direction: SortDirection
}

// One column definition — T is the row type
export interface ColumnDef<T> {
  key: string                       // unique column id, used as React key on <th> and <td>
  header: string                    // column header label
  accessor: (row: T) => ReactNode   // cell renderer — receives the full row, returns anything renderable
  sortKey?: SortableKeys<T>         // which field to sort by; omit for non-sortable columns
  className?: string                // optional Tailwind classes added to <td>
  headerClassName?: string          // optional Tailwind classes added to <th>
}

// Props for SortableTable
export interface SortableTableProps<T> {
  data: T[]
  columns: ColumnDef<T>[]
  getRowKey: (row: T) => string   // extract a stable unique key for each row
  defaultSort?: TableSortKey<T>   // initial sort as a "field_direction" string — no sort applied if omitted
}

// ── Conditional type demonstration ───────────────────────────────────────────
// SelectionProps is NOT used in SortableTableProps<T> in this module.
// It demonstrates how conditional types make props mutually exclusive:
//   { selectable: true }  → selectedKeys and onToggleRow are required
//   { selectable?: false } → selectedKeys and onToggleRow do not exist on the type
export type SelectionProps =
  | { selectable: true; selectedKeys: Set<string>; onToggleRow: (key: string) => void }
  | { selectable?: false }
```

### 6.2 `src/components/SortableTable.tsx` — NEW

**Wireframe (Orders, default sort Date `↓`):**

```
┌──────────────────────────────────────────────────────────────────┐
│  bg-white rounded-xl shadow-sm border border-gray-100            │
│  overflow-x-auto                                                 │
│                                                                  │
│  ORDER #   DATE ↓         STATUS        ITEMS     TOTAL         │
│  ────────────────────────────────────────────────────────────── │
│  ORD-003   Jul 20, 2025   [Processing]  3 items   $29.97        │
│  ORD-002   Jul 1, 2025    [Shipped]     1 item    $149.99       │
│  ORD-001   Jun 15, 2025   [Delivered]   2 items   $139.97       │
│                                                                  │
│  ^ DATE has cursor-pointer; ITEMS does not (no sortKey)          │
└──────────────────────────────────────────────────────────────────┘
```

**Requirements:**
- Imports: `useState`, `useMemo` from `react`; `ColumnDef`, `SortableTableProps`, `SortState`, `SortableKeys`, `TableSortKey` from `@/types/table`
- Use a **function declaration**, not an arrow function — arrow function generics in `.tsx` require `<T,>` or `<T extends object>` to prevent the parser treating `<T>` as JSX; function declarations do not:
  ```tsx
  function SortableTable<T>({ data, columns, getRowKey, defaultSort }: SortableTableProps<T>) {
  ```
- Parse `defaultSort` into initial sort state — a module-level helper function, defined above `SortableTable`:
  ```tsx
  // Splits a TableSortKey<T> literal like 'createdAt_desc' into { key, direction }.
  // Splits at the LAST underscore, not the first: SortDirection ('asc' | 'desc')
  // never contains an underscore, but a key derived from T might.
  function parseSortKey<T>(sortKey: TableSortKey<T>): SortState<T> {
    const i = sortKey.lastIndexOf('_')
    const direction = sortKey.slice(i + 1) === 'asc' ? 'asc' : 'desc'
    return { key: sortKey.slice(0, i) as SortableKeys<T>, direction }
  }
  ```
  `direction` is inferred as `'asc' | 'desc'` from the conditional expression — no cast needed. `key` requires one cast: TypeScript cannot verify through the unresolved generic `T` that slicing off everything before the last `_` produces exactly `SortableKeys<T>`; the cast is sound because `TableSortKey<T>`'s own definition guarantees that shape for any string that reaches this function with that static type — the same "cast forced by an unresolved generic, not evasion" reasoning used below for the sort comparator's cast. `parseSortKey` is not exported — it is a private implementation detail of `SortableTable.tsx`.
- Sort state:
  ```tsx
  const [sort, setSort] = useState<SortState<T> | null>(
    defaultSort ? parseSortKey(defaultSort) : null
  )
  ```
- Memoized sorted array:
  ```tsx
  const sorted = useMemo(() => {
    if (!sort) return data
    return [...data].sort((a, b) => {
      const av = a[sort.key] as string | number
      const bv = b[sort.key] as string | number
      if (av < bv) return sort.direction === 'asc' ? -1 : 1
      if (av > bv) return sort.direction === 'asc' ? 1 : -1
      return 0
    })
  }, [data, sort])
  ```
  The `as string | number` cast is sound: `sort.key` is `SortableKeys<T>`, which the mapped type constrains to keys with primitive values. TypeScript cannot verify this through the unresolved generic, so the cast is required — it is not evasion of type checking.
- Sort toggle:
  ```tsx
  function handleSort(key: SortableKeys<T>) {
    setSort(prev =>
      prev?.key === key
        ? { key, direction: prev.direction === 'asc' ? 'desc' : 'asc' }
        : { key, direction: 'asc' }
    )
  }
  ```
  First click on a column → sort ascending. Second click same column → toggle to descending. Click a different column → sort new column ascending.
- Full JSX structure:
  ```tsx
  return (
    <div className="bg-white rounded-xl shadow-sm border border-gray-100 overflow-x-auto">
      <table className="w-full text-sm">
        <thead>
          <tr className="border-b border-gray-200">
            {columns.map(col => (
              <th
                key={col.key}
                className={[
                  'px-4 py-3 text-left text-xs font-semibold text-gray-500 uppercase tracking-wide whitespace-nowrap',
                  col.sortKey ? 'cursor-pointer select-none hover:text-gray-900' : '',
                  col.headerClassName ?? '',
                ].join(' ')}
                onClick={col.sortKey ? () => handleSort(col.sortKey!) : undefined}
              >
                {col.header}
                {col.sortKey && sort?.key === col.sortKey && (
                  <span className="ml-1 text-blue-600">
                    {sort.direction === 'asc' ? '↑' : '↓'}
                  </span>
                )}
              </th>
            ))}
          </tr>
        </thead>
        <tbody className="divide-y divide-gray-100">
          {sorted.map(row => (
            <tr key={getRowKey(row)} className="bg-white hover:bg-gray-50 transition-colors">
              {columns.map(col => (
                <td key={col.key} className={`px-4 py-3 ${col.className ?? ''}`}>
                  {col.accessor(row)}
                </td>
              ))}
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  )
  ```
- Default export: `export default SortableTable`
- No `any` types; two casts total — `as string | number` in the sort comparator and `as SortableKeys<T>` in `parseSortKey` — both sound narrowings forced by the unresolved generic `T`, not evasions of type checking

```tsx
const ORDER_COLUMNS = [
  {
    key: 'id',
    header: 'Order #',
    accessor: (o: Order) => o.id,
    sortKey: 'id',
  },
  {
    key: 'date',
    header: 'Date',
    accessor: (o: Order) =>
      new Date(o.createdAt).toLocaleDateString('en-US', {
        month: 'short',
        day: 'numeric',
        year: 'numeric',

    sortKey: 'createdAt',

    key: 'status',
    header: 'Status',
    accessor: (o: Order) => (
      <span
        className={`text-xs font-medium px-2 py-0.5 rounded-full ${badgeClasses[o.status]}`}
      >
        {o.status.charAt(0).toUpperCase() + o.status.slice(1)}
      </span>
    ),
    sortKey: 'status',
  },
  {
    key: 'items',
    header: 'Items',
    accessor: (o: Order) => {
      const n = o.items.length
      return `${n} ${n === 1 ? 'item' : 'items'}`
    },
    // no sortKey — Items is non-sortable
  },
  {
    key: 'total',
    header: 'Total',
    accessor: (o: Order) => `$${o.total.toFixed(2)}`,
    sortKey: 'total',
    className: 'font-medium text-gray-900',
  },
] satisfies ColumnDef<Order>[]
```

**`satisfies` behaviour:** TypeScript validates that each object matches `ColumnDef<Order>`. A wrong sort key — e.g., `sortKey: 'items'` — is a compile-time error because `'items'` is not in `SortableKeys<Order>`. Unlike `: ColumnDef<Order>[]` annotation, `satisfies` does not widen the type; each object retains its inferred literal types.

## 8. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| Generic component | `SortableTable<T>` | Row type flows through to column definitions and sort state — one component works for any row shape without `any` |
| Function declaration for generic `.tsx` | `SortableTable.tsx` | Arrow function generics in `.tsx` need `<T,>` to disambiguate `<T>` from JSX; function declarations do not |
| Mapped type | `{ [K in keyof T]: ... }[keyof T]` in `table.ts` | Transforms a type's property map — iterate all keys, produce a value per key, index to collapse to a union |
| Conditional type inside a mapped type | `T[K] extends string \| number \| boolean ? K : never` | The conditional is the filter: failing keys produce `never`, which disappears from the union when indexed |
| Template literal type | `TableSortKey<T>` in `table.ts`, used as `SortableTableProps<T>.defaultSort` | Generates a union of string literals by combining two other unions — TypeScript ensures `defaultSort` can only ever be assigned a real column+direction combination |
| `string &` intersection in template literals | In `TableSortKey<T>` | `keyof T` may include `symbol` keys; the intersection narrows to string-only keys, satisfying the template literal constraint |
| `satisfies` operator | `ORDER_COLUMNS satisfies ColumnDef<Order>[]` | Validates shape against a type without widening the inferred type — wrong `sortKey` values are compile-time errors; literal types are preserved |
| `satisfies` vs type annotation | Contrast in spec | `: ColumnDef<Order>[]` widens and loses literal types. `satisfies ColumnDef<Order>[]` validates and preserves — the distinction is meaningful when downstream code depends on the narrow type |
| Casting out of an unresolved generic | `parseSortKey<T>` in `SortableTable.tsx` | Splitting a `TableSortKey<T>` string at runtime loses the compiler's view of `SortableKeys<T>`; the resulting cast is sound because the input's static type already guarantees the shape — same reasoning as the sort comparator's cast |
| Module-level column definitions | `ORDER_COLUMNS` at file scope | Constants with no dependency on props or state belong at module level — consistent with why `lazy()` calls are at module level in v0.12 |
| `useMemo` for derived sort | `sorted` in `SortableTable.tsx` | Sorting is O(n log n); `useMemo` skips it when neither `data` nor `sort` changed — reinforces the v0.11 memoization pattern |
