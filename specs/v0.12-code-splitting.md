# v0.12 — Code Splitting

### Product Requirement Specification

---

## 1. Overview

**Goal:** Reduce ReactMart's initial JavaScript bundle by converting route-level page imports from eager (`import`) to lazy (`React.lazy` + `import()`). Add a `<Suspense>` boundary around the route tree with a `Spinner` fallback component, and introduce a stub `AdminDashboard` page that demonstrates a new lazy route from scratch. Run `vite build` and `vite-bundle-visualizer` to verify the split and measure the result.

**End result:** `pnpm build` produces separate `.js` chunks in `dist/assets/` for `ProductDetail`, `Cart`, `Profile`, `Orders`, and `AdminDashboard` instead of bundling them all into one main file. The landing page (`Home`) loads with no spinner on the first visit. Navigating to any other route for the first time shows a brief spinner while the chunk downloads; subsequent visits to the same route skip the network request entirely (the chunk is browser-cached). Running `npx vite-bundle-visualizer` opens a treemap that visually confirms each page lives in its own chunk and the main bundle no longer contains their code.

**Why this comes after v0.11:** v0.11 optimises what the browser re-renders at runtime (fewer unnecessary renders). v0.12 optimises what the browser downloads at startup (smaller initial bundle). Profiling v0.11's output first gives a clean, render-optimised baseline to measure bundle savings against. The two techniques are orthogonal — each targets a different axis of "fast."

### Module Constraints

- **No Vite config changes.** Vite turns every `import()` call into a separate chunk automatically. No `rollupOptions.output.manualChunks` needed for route splitting.
- **`Home` stays eager.** It is the entry point; lazy-loading it would show a spinner on every first visit to the site — worse UX for zero gain.
- **`NotFound` stays eager.** It is tiny and is the wildcard catch-all; keeping it eager avoids any risk of a chunk-load failure preventing 404 from rendering.
- **One `<Suspense>` boundary.** Wrap the entire `<Routes>` tree in a single `<Suspense fallback={<Spinner />}>`. Per-route Suspense boundaries add boilerplate without adding clarity at this learning stage.
- **AdminDashboard is a stub.** No real admin functionality — a heading and a "coming soon" message. Its only purpose is to demonstrate adding a new lazy route from scratch.
- **No auth gating on `/admin`.** Route guards are a v0.7 concern. `/admin` is publicly accessible in v0.12.
- **Tailwind only.** No inline styles, no CSS modules.
- **React 19 JSX transform.** `import React from 'react'` is not needed; `lazy` and `Suspense` are named imports from `'react'`.

### Out of Scope (do not build in this module)

| Feature | Planned for |
| --- | --- |
| Component-level lazy loading (below route granularity) | future |
| Prefetching chunks on hover / `<link rel="prefetch">` | future |
| `React.lazy` + `Suspense` for non-route async data | v0.9/v0.10 already covered this via TanStack Query |
| `ErrorBoundary` to handle chunk-load failures (network error) | future |
| Auth-gated admin route | v0.7 pattern; out of scope for this module |
| Real admin dashboard functionality | v0.15+ |
| `rollupOptions.manualChunks` for vendor splitting | future |
| SSR / streaming SSR | future |

## 4. Bundle Split Points

This table documents which modules are lazy-loaded, the chunk Vite produces for each, and the trigger that causes the browser to fetch it. Use this as a reference when verifying `dist/assets/` after `pnpm build`.

| Import style | Page | Chunk filename (prefix) | Initial bundle? | Loaded when |
| --- | --- | --- | --- | --- |
| `import` (eager) | `Home` | _(included in `index-[hash].js`)_ | yes | Every visit — landing page |
| `import` (eager) | `NotFound` | _(included in `index-[hash].js`)_ | yes | Every visit — wildcard always ready |
| `lazy(() => import(...))` | `ProductDetail` | `ProductDetail-[hash].js` | no | User navigates to `/products/:id` |
| `lazy(() => import(...))` | `Cart` | `Cart-[hash].js` | no | User navigates to `/cart` |
| `lazy(() => import(...))` | `Profile` | `Profile-[hash].js` | no | User navigates to `/profile` |
| `lazy(() => import(...))` | `Orders` | `Orders-[hash].js` | no | User navigates to `/orders` |
| `lazy(() => import(...))` | `AdminDashboard` | `AdminDashboard-[hash].js` | no | User navigates to `/admin` |

**How Vite names chunks:** By default, Vite derives the chunk filename from the imported module's filename. `lazy(() => import('@/pages/ProductDetail'))` produces `ProductDetail-[hash].js`. The hash changes on every build if the file content changes, enabling long-lived cache headers in production.

**What the browser does:** The first time the user navigates to a lazy route, the browser makes one additional `<script>` request to fetch that chunk. React renders `<Spinner />` in the `<Suspense>` fallback while the download completes. Once resolved, React unmounts the fallback and mounts the page. On all subsequent navigations to the same route within the session (and across sessions while the chunk is browser-cached), no additional network request is made.

### 6.1 `src/components/Spinner.tsx` — NEW

**Wireframe (Suspense fallback — replaces page content while chunk loads):**

```
┌────────────────────────────────────────────────────────────┐
│  ■ Hello Shop   Home  Orders  Profile  Admin  Cart [n]     │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                                                            │
│                    ◌  ←  animate-spin                      │
│                  (blue circular spinner, 32 × 32 px)       │
│                                                            │
│                                                            │
└────────────────────────────────────────────────────────────┘
  Replaces the route's page component until its chunk resolves.
  The Header stays mounted — <Suspense> wraps <Routes>, not <App>.
```

**CSS classes:**

| Element | Classes |
| --- | --- |
| Wrapper `<div>` | `min-h-[400px] flex items-center justify-center` |
| `<svg>` | `animate-spin w-8 h-8 text-blue-600` |

**Requirements:**
- No props — purely presentational
- Use the SVG circular-spinner pattern (one `<circle>` for the track, one `<path>` for the arc):

```tsx
export default function Spinner() {
  return (
    <div className="min-h-[400px] flex items-center justify-center">
      <svg
        className="animate-spin w-8 h-8 text-blue-600"
        xmlns="http://www.w3.org/2000/svg"
        fill="none"
        viewBox="0 0 24 24"
        aria-label="Loading"
        role="status"
      >
        <circle
          className="opacity-25"
          cx="12"
          cy="12"
          r="10"
          stroke="currentColor"
          strokeWidth="4"
        />
        <path
          className="opacity-75"
          fill="currentColor"
          d="M4 12a8 8 0 018-8V0C5.373 0 0 5.373 0 12h4z"
        />
      </svg>
    </div>
  )
}
```

- `role="status"` and `aria-label="Loading"` satisfy basic screen-reader accessibility
- `min-h-[400px]` vertically centres the spinner in the content area without repositioning the sticky header

### 6.3 `src/App.tsx` — UPDATED

**What changes:** Five eager `import` statements for page components are replaced with `lazy()` calls. A `<Suspense>` boundary wraps the `<Routes>` tree. The `/admin` route is added.

**Requirements:**
- Add `lazy` and `Suspense` to the named import from `'react'`
- Replace the five page-component `import` statements with `lazy` calls — keep `Home` and `NotFound` as eager imports:

```tsx
import { lazy, Suspense } from 'react'
import { Routes, Route } from 'react-router-dom'
import Header from '@/components/Header'
import Spinner from '@/components/Spinner'
import Home from '@/pages/Home'
import NotFound from '@/pages/NotFound'

const ProductDetail = lazy(() => import('@/pages/ProductDetail'))
const Cart = lazy(() => import('@/pages/Cart'))
const Profile = lazy(() => import('@/pages/Profile'))
const Orders = lazy(() => import('@/pages/Orders'))
const AdminDashboard = lazy(() => import('@/pages/AdminDashboard'))
```

- Wrap `<Routes>` in `<Suspense fallback={<Spinner />}>`:

```tsx
export default function App() {
  return (
    <>
      <Header />
      <main className="bg-gray-50 min-h-screen">
        <Suspense fallback={<Spinner />}>
          <Routes>
            <Route path="/" element={<Home />} />
            <Route path="/products/:id" element={<ProductDetail />} />
            <Route path="/cart" element={<Cart />} />
            <Route path="/profile" element={<Profile />} />
            <Route path="/orders" element={<Orders />} />
            <Route path="/admin" element={<AdminDashboard />} />
            <Route path="*" element={<NotFound />} />
          </Routes>
        </Suspense>
      </main>
    </>
  )
}
```

- `lazy()` calls are at module level, not inside the component — if declared inside the component function they re-create the lazy reference on every render and break React's ability to cache the loaded module
- `<Suspense>` is placed inside `<main>` so the Header remains visible during chunk loading
- All existing `<Route>` paths are unchanged — lazy loading is transparent to React Router

## 8. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| `React.lazy` | `App.tsx` | Wraps a dynamic `import()` to create a lazily-loadable component; React defers rendering it until the chunk resolves |
| `Suspense` | `App.tsx` | Provides the fallback UI shown while one or more lazy children are loading; must be an ancestor of every `lazy()` component |
| Dynamic `import()` | Inside each `lazy()` call | The JavaScript language feature that Vite (Rollup) splits into a separate chunk; each unique `import()` path → one chunk |
| Eager vs lazy loading | `Home` / `NotFound` vs the other 5 pages | Eager imports land in the main bundle (zero extra requests); lazy imports arrive on demand. The landing page and tiny utilities belong eager; heavy pages belong lazy |
| Route-based code splitting | `App.tsx` route tree | The most impactful split granularity — each page is its own entry point and its dependencies travel with it |
| Chunk naming | `dist/assets/` after `pnpm build` | Vite derives the chunk filename from the imported module's filename; the hash suffix changes when file content changes, enabling safe long-lived CDN caching |
| `<Suspense>` placement | Inside `<main>`, wrapping `<Routes>` | Placing `<Suspense>` inside `<main>` keeps the Header mounted and visible during loading — the spinner only occupies the content area |
| Module-level `lazy()` calls | Top of `App.tsx` | Declaring `lazy()` outside the component function means the lazy reference is stable across renders; declaring it inside would create a new reference on every render and break the cache |
| Browser chunk caching | Network tab observation | Once a chunk is fetched, the browser caches it (controlled by cache headers); navigating back to the same route shows no new JS request — the component re-mounts from memory |
| `vite-bundle-visualizer` | Post-build analysis step | A treemap that reveals which modules contribute to which chunks; use it to identify pages that are unexpectedly large or dependencies that are duplicated across chunks |
