# v0.5 — Custom Hooks with TypeScript

### Product Requirement Specification

---

## 1. Overview

**Goal:** Extract reusable stateful logic into three generic custom hooks — `useDebounce`, `useLocalStorage`, and `useWindowSize` — and wire `useDebounce` into the Home page search to add a 300 ms delay before filtering. Set up Vitest with `renderHook` and write a test suite for each hook.

**End result:** The search bar on Home now waits 300 ms after the user stops typing before filtering products. Category and price filters remain live. All three hooks are unit-tested with `renderHook`. `pnpm test:run` passes 10 tests in under a second.

**Why this comes after v0.4:** Custom hooks are the right abstraction once you have real features to extract from. `useDebounce` is only useful once there is a search input to debounce (added in v0.4). The testing infrastructure (Vitest + `renderHook`) can be introduced here because all three hooks are pure logic with no render output — the simplest possible context for learning `renderHook`.

### 5.2 `src/hooks/useDebounce.ts` — NEW

**Hook signature:**

```
useDebounce<T>(value: T, delay: number): T
```

**How it behaves:**

```
value changes → timer starts (delay ms)
value changes again before timer fires → old timer cancelled, new timer starts
timer fires → debounced value updates to latest value
```

**Requirements:**
- Named export: `export function useDebounce<T>(value: T, delay: number): T`
- `useState<T>` initialized to `value` — returns the debounced value
- `useEffect` with `[value, delay]` deps:
  - Schedules `setTimeout(() => setDebounced(value), delay)`
  - Returns `() => clearTimeout(timer)` as cleanup — this is what implements debouncing (the previous timer is cleared before a new one starts)
- No other logic — 12 lines total

**Full implementation:**

```ts
import { useEffect, useState } from "react";

export function useDebounce<T>(value: T, delay: number): T {
  const [debounced, setDebounced] = useState<T>(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}
```

**Why `delay` is in the deps array:** If the caller ever changes `delay` (e.g., switches from 300 ms to 500 ms based on a setting), the effect re-runs with the new delay. Omitting it would cause a stale closure bug that's hard to debug.

### 5.3 `src/hooks/useLocalStorage.ts` — NEW

**Hook signature:**

```
useLocalStorage<T>(key: string, initialValue: T): [T, (value: T) => void]
```

**How it behaves:**

```
mount (nothing stored) → returns [initialValue, setValue]
mount (value exists in localStorage) → returns [parsed value, setValue]
setValue(x) → updates React state + writes JSON.stringify(x) to localStorage
```

**Requirements:**
- Named export: `export function useLocalStorage<T>(key: string, initialValue: T): [T, (value: T) => void]`
- `useState<T>` with **lazy initializer** (function form):
  - Calls `localStorage.getItem(key)` once on mount
  - Returns `JSON.parse(item) as T` if `item !== null`, else `initialValue`
  - Wrapped in `try/catch` — returns `initialValue` on any parse error
- `setValue` function:
  - Calls `setStored(value)` to update React state
  - Calls `localStorage.setItem(key, JSON.stringify(value))` to persist
  - Wrapped in `try/catch` — silent on failure (private browsing, storage quota)
- Returns `[stored, setValue]` as a tuple

**Full implementation:**

```ts
import { useState } from "react";

export function useLocalStorage<T>(key: string, initialValue: T): [T, (value: T) => void] {
  const [stored, setStored] = useState<T>(() => {
    try {
      const item = localStorage.getItem(key);
      return item !== null ? (JSON.parse(item) as T) : initialValue;
    } catch {
      return initialValue;
    }
  });

  const setValue = (value: T): void => {
    try {
      setStored(value);
      localStorage.setItem(key, JSON.stringify(value));
    } catch {
      // silent: localStorage unavailable (private browsing, quota exceeded)
    }
  };

  return [stored, setValue];
}
```

**Why `item !== null` instead of `!item`:** `localStorage.getItem` returns `null` when the key is absent. If someone stored the JSON string `"null"` or `"0"` or `""`, those are valid stored values that should be returned — not treated as absent. `!item` would incorrectly fall back to `initialValue` for those cases.

**Why lazy initializer (function form of `useState`):** The function runs once on mount. If the initializer were `useState<T>(JSON.parse(localStorage.getItem(key)!))`, `localStorage.getItem` would be called on every render — even though `useState`'s initial value is only used once. The function form avoids the redundant calls.

### 5.4 `src/hooks/useWindowSize.ts` — NEW

**Hook signature:**

```
useWindowSize(): { width: number; height: number }
```

**How it behaves:**

```
mount → reads window.innerWidth / window.innerHeight immediately
window "resize" event fires → reads again, triggers re-render
unmount → removes event listener
```

**Requirements:**
- Named export: `export function useWindowSize(): WindowSize`
- Define `interface WindowSize { width: number; height: number }` above the function (not exported — internal to this file)
- `useState<WindowSize>` initialized to `{ width: window.innerWidth, height: window.innerHeight }` — reads from `window` directly so there is no undefined/0 state on first render
- `useEffect` with `[]` (empty) deps:
  - Defines `const onResize = (): void => setSize({ width: window.innerWidth, height: window.innerHeight })`
  - Calls `window.addEventListener("resize", onResize)`
  - Returns `() => window.removeEventListener("resize", onResize)` as cleanup
- Returns `size`

**Full implementation:**

```ts
import { useEffect, useState } from "react";

interface WindowSize {
  width: number;
  height: number;
}

export function useWindowSize(): WindowSize {
  const [size, setSize] = useState<WindowSize>({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    const onResize = (): void =>
      setSize({ width: window.innerWidth, height: window.innerHeight });
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);

  return size;
}
```

**Why empty deps `[]`:** The effect registers one listener for the lifetime of the component. `onResize` does not close over any state — it reads `window.innerWidth` fresh on each call — so it never goes stale. Adding `size` to the deps would register/unregister the listener on every resize, which is wasteful and semantically wrong.

**Why `removeEventListener` in cleanup:** Without it, every hot-reload in development registers a new listener without removing the old one. After 10 hot-reloads, 10 listeners are firing on every resize. This is a real problem in development and a memory leak in production if the component unmounts.

```tsx
import { filterSchema, FilterValues, CATEGORIES, Category } from "@/schemas/filter";
import { MOCK_PRODUCTS } from "@/data/products";
import { useDebounce } from "@/hooks/useDebounce";

      </div>
      <div className="flex flex-col md:flex-row gap-6">
        <div className="w-full md:w-56 shrink-0">
          <FilterPanel register={register} errors={errors} />
        </div>
        <div className="flex-1 min-w-0">
          <ProductGrid products={filteredProducts} />
        </div>
      </div>
    </div>
  );
}
```

### 5.6 `src/hooks/__tests__/useDebounce.test.ts` — NEW

**Test structure:**

```
describe("useDebounce")
  ├── returns the initial value immediately
  ├── does not update before the delay elapses
  ├── updates after the delay elapses
  └── resets the timer on rapid value changes
```

**Key patterns:**

- `vi.useFakeTimers()` in `beforeEach`, `vi.useRealTimers()` in `afterEach` — fake timers replace `setTimeout`/`clearTimeout` with synchronous equivalents controlled by `vi.advanceTimersByTime(ms)`
- `renderHook(({ value }) => useDebounce(value, 300), { initialProps: { value: "hello" } })` — the `initialProps` pattern allows changing the hook's input via `rerender({ value: "world" })` without rewriting the callback
- `act(() => { vi.advanceTimersByTime(ms); })` — wraps timer advancement in `act` so React state updates are flushed

**Full implementation:**

```ts
import { renderHook, act } from "@testing-library/react";
import { afterEach, beforeEach, describe, expect, it, vi } from "vitest";
import { useDebounce } from "../useDebounce";

describe("useDebounce", () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });
  afterEach(() => {
    vi.useRealTimers();
  });

  it("returns the initial value immediately", () => {
    const { result } = renderHook(() => useDebounce("hello", 300));
    expect(result.current).toBe("hello");
  });

  it("does not update before the delay elapses", () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 300),
      { initialProps: { value: "hello" } }
    );
    rerender({ value: "world" });
    act(() => {
      vi.advanceTimersByTime(100);
    });
    expect(result.current).toBe("hello");
  });

  it("updates after the delay elapses", () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 300),
      { initialProps: { value: "hello" } }
    );
    rerender({ value: "world" });
    act(() => {
      vi.advanceTimersByTime(300);
    });
    expect(result.current).toBe("world");
  });

  it("resets the timer on rapid value changes", () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 300),
      { initialProps: { value: "a" } }
    );
    rerender({ value: "ab" });
    act(() => {
      vi.advanceTimersByTime(200); // 200ms since "ab" — timer not fired
    });
    rerender({ value: "abc" });
    act(() => {
      vi.advanceTimersByTime(200); // 200ms since "abc" — timer reset, not fired
    });
    expect(result.current).toBe("a"); // still showing original
    act(() => {
      vi.advanceTimersByTime(100); // now 300ms since "abc" was set
    });
    expect(result.current).toBe("abc");
  });
});
```

### 5.7 `src/hooks/__tests__/useLocalStorage.test.ts` — NEW

**Test structure:**

```
describe("useLocalStorage")
  ├── returns the initial value when nothing is stored
  ├── persists a new value to localStorage
  ├── reads a pre-existing value from localStorage on mount
  └── works with array values
```

**Key patterns:**

- `localStorage.clear()` in `beforeEach` — jsdom's `localStorage` persists between tests in the same file; clearing it prevents test interference
- `result.current[0]` — the stored value; `result.current[1]` — the `setValue` function
- `act(() => { result.current[1](99); })` — calling `setValue` triggers a state update; wrap in `act` so React flushes it before the assertion
- `expect(localStorage.getItem("key")).toBe("99")` — verify the raw localStorage string was written, not just React state

**Full implementation:**

```ts
import { renderHook, act } from "@testing-library/react";
import { beforeEach, describe, expect, it } from "vitest";
import { useLocalStorage } from "../useLocalStorage";

describe("useLocalStorage", () => {
  beforeEach(() => {
    localStorage.clear();
  });

  it("returns the initial value when nothing is stored", () => {
    const { result } = renderHook(() => useLocalStorage("key", 42));
    expect(result.current[0]).toBe(42);
  });

  it("persists a new value to localStorage", () => {
    const { result } = renderHook(() => useLocalStorage("key", 0));
    act(() => {
      result.current[1](99);
    });
    expect(result.current[0]).toBe(99);
    expect(localStorage.getItem("key")).toBe("99");
  });

  it("reads a pre-existing value from localStorage on mount", () => {
    localStorage.setItem("key", JSON.stringify("saved"));
    const { result } = renderHook(() => useLocalStorage("key", "default"));
    expect(result.current[0]).toBe("saved");
  });

  it("works with array values", () => {
    const { result } = renderHook(() => useLocalStorage<string[]>("list", []));
    act(() => {
      result.current[1](["a", "b"]);
    });
    expect(result.current[0]).toEqual(["a", "b"]);
    expect(localStorage.getItem("list")).toBe('["a","b"]');
  });
});
```

### 5.8 `src/hooks/__tests__/useWindowSize.test.ts` — NEW

**Test structure:**

```
describe("useWindowSize")
  ├── returns current window dimensions on mount
  └── updates when the window is resized
```

**Key patterns:**

- `Object.defineProperty(window, "innerWidth", { writable: true, configurable: true, value: 1024 })` — jsdom defines `window.innerWidth` as non-configurable by default. Using `Object.defineProperty` with `configurable: true` makes it redefinable in subsequent tests. **`configurable: true` is required** — omitting it causes a `TypeError: Cannot redefine property: innerWidth` on the second test.
- `window.dispatchEvent(new Event("resize"))` — triggers the `"resize"` listener registered by the hook
- `act(...)` — wraps both the property reassignment and `dispatchEvent` so React flushes the state update before the assertion

**Full implementation:**

```ts
import { renderHook, act } from "@testing-library/react";
import { beforeEach, describe, expect, it } from "vitest";
import { useWindowSize } from "../useWindowSize";

describe("useWindowSize", () => {
  beforeEach(() => {
    Object.defineProperty(window, "innerWidth", {
      writable: true,
      configurable: true,
      value: 1024,
    });
    Object.defineProperty(window, "innerHeight", {
      writable: true,
      configurable: true,
      value: 768,
    });
  });

  it("returns current window dimensions on mount", () => {
    const { result } = renderHook(() => useWindowSize());
    expect(result.current.width).toBe(1024);
    expect(result.current.height).toBe(768);
  });

  it("updates when the window is resized", () => {
    const { result } = renderHook(() => useWindowSize());
    act(() => {
      Object.defineProperty(window, "innerWidth", {
        writable: true,
        configurable: true,
        value: 375,
      });
      Object.defineProperty(window, "innerHeight", {
        writable: true,
        configurable: true,
        value: 812,
      });
      window.dispatchEvent(new Event("resize"));
    });
    expect(result.current.width).toBe(375);
    expect(result.current.height).toBe(812);
  });
});
```

## 7. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| Generic hook `<T>` | `useDebounce<T>`, `useLocalStorage<T>` | The caller never writes a type annotation — TypeScript infers `T` from the argument. Same hook works for `string`, `number`, `string[]`, or any value. |
| `useEffect` cleanup | `useDebounce`, `useWindowSize` | The function returned from `useEffect` runs before the next effect and on unmount. For timers: cancels the previous timer. For listeners: removes the handler. Forgetting cleanup is the most common hook bug. |
| Lazy `useState` initializer | `useLocalStorage` | `useState(() => expensiveRead())` — the function runs once on mount. `useState(expensiveRead())` runs on every render. The function form avoids redundant `localStorage.getItem` calls. |
| Tuple return type | `useLocalStorage` | `[T, (value: T) => void]` mirrors `useState`'s return type. Callers can destructure with custom names: `const [theme, setTheme] = useLocalStorage("theme", "light")`. |
| `renderHook` | All three test files | Renders a hook in a minimal React component and exposes its return value via `result.current`. The only way to test hook logic without a full component. |
| `initialProps` + `rerender` | `useDebounce` tests | `renderHook(fn, { initialProps })` makes the hook accept changing inputs. `rerender({ value: "new" })` changes the input between assertions — simulating what happens when a user types. |
| Fake timers (`vi.useFakeTimers`) | `useDebounce` tests | Replaces `setTimeout`/`clearTimeout` with synchronous mocks. `vi.advanceTimersByTime(300)` is equivalent to waiting 300 ms without actually waiting. Essential for testing time-dependent logic. |
| `act(...)` in tests | All three test files | Wraps anything that causes a state update — `setValue`, `vi.advanceTimersByTime`, `dispatchEvent` — so React flushes updates synchronously before the assertion. Omitting `act` causes "not wrapped in act" warnings and flaky tests. |
| `Object.defineProperty` for mocking | `useWindowSize` tests | jsdom defines `window.innerWidth` as non-writable. `Object.defineProperty` with `{ writable: true, configurable: true }` overrides it. `configurable: true` is required so it can be redefined again in the next test. |
