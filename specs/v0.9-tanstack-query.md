# v0.9 — TanStack Query

### Product Requirement Specification

---

## 1. Overview

**Goal:** Replace Hello Shop's static `MOCK_PRODUCTS` import with real asynchronous data fetching using TanStack Query v5 and Mock Service Worker (MSW v2). Add loading and error states to the product listing and detail pages, configure query caching with `staleTime`, and observe how the cache eliminates redundant network requests.

**End result:** Navigating to `/` triggers a `GET /api/products` request intercepted by MSW. The page shows a loading state briefly, then renders the product grid. Navigating to `/products/:id` triggers a `GET /api/products/:id` request. Navigating back to `/` does not trigger a second request — the cache is fresh. Navigating to an invalid product ID (`/products/999`) shows a "Product not found." error state immediately, with no retry delay. All data fetching logic lives in reusable fetcher functions typed against the `Product` interface.

**Why this comes after v0.3:** TanStack Query is a data-fetching wrapper around `fetch` — it needs typed interfaces (`Product`) and page-level components (`Home`, `ProductDetail`) already in place. The routing layer (v0.3) determines where loading and error states are rendered. v0.9 deliberately avoids mutations — no POST, no cache invalidation — so the learning focus stays on query setup, caching, and async UI states.

### Module Constraints

- **API prefix is `/api/`.** The fetch URLs are `/api/products` and `/api/products/:id`, not `/products`. A bare `/products` fetch would read confusingly next to the React Router `/products/:id` browser route — the `/api/` prefix visually separates the two layers even though they never actually conflict.
- **MSW stays in dev only.** `worker.start()` is guarded by `import.meta.env.DEV`. Production builds never load the service worker.
- **`MOCK_PRODUCTS` is not removed.** The array in `src/data/products.ts` becomes the backing data for MSW handlers. Pages stop importing it directly; MSW handlers still do.
- **No real backend.** MSW intercepts `fetch()` at the service worker level — no Express, no proxy, no real HTTP server.
- **MSW v2 API.** Use `http` (not `rest`) and `HttpResponse` from `"msw"`. The v1 `rest.get()` API does not exist in v2.
- **TanStack Query v5 API.** Use `isPending` (not `isLoading`) for the "no data + currently fetching" state. In v5, `isLoading` means `isPending && isFetching` — it is false for a disabled query that hasn't fetched yet, which is a subtly different concept. Always use `isPending` for the initial load guard.
- **`retry: false` on product detail.** MSW returns a 404 for unknown IDs. TanStack Query retries failed queries 3 times by default, adding 30+ seconds of waiting before showing an error. Disable retries on this query.
- **No DevTools in this module.** `@tanstack/react-query-devtools` is a useful companion but is out of scope — install it independently if desired.
- **No mutations.** `useMutation`, `queryClient.invalidateQueries`, and optimistic updates are covered in v0.10.

### Out of Scope (do not build in this module)

| Feature | Planned for |
| --- | --- |
| Mutations, optimistic updates | v0.10 |
| Infinite scroll / pagination | v0.10 |
| React Query DevTools UI panel | self-directed |
| Error boundary integration | future |
| Search / filter state in query key | v0.10 |

## 4. API Endpoint Reference

These are the two URLs MSW intercepts. Both are relative paths resolved against `localhost:5173`.

| Method | URL | Response shape | Status codes |
| --- | --- | --- | --- |
| `GET` | `/api/products` | `Product[]` | 200 (always) |
| `GET` | `/api/products/:id` | `Product` | 200 (found), 404 (not found) |

**Query key conventions:**

| Query | Query key array | Scope |
| --- | --- | --- |
| All products | `["products"]` | Invalidating `["products"]` clears this cache entry |
| Single product | `["product", id]` | `id` is the string from `useParams` — each product ID gets its own cache entry |

## 5. Shared UI State Patterns

Each page that fetches data renders three states: loading, error, and success. The loading and error states reuse the page's outer container but substitute the content.

| State | Page | Element | Classes |
| --- | --- | --- | --- |
| Loading text | Home | `<p>` | `text-gray-500` |
| Error text | Home | `<p>` | `text-gray-500` |
| Loading text | ProductDetail | `<p>` | `text-gray-500` |
| Error not-found | ProductDetail | `<span>` + back button | Same classes as v0.3 inline not-found state |

> **Design rule:** No skeleton loaders or spinners in v0.9. Plain text states keep the focus on data fetching logic, not animation.

Both pages use the same outer container as their success state — loading and error returns early with the same container `div` class so the page layout does not shift.

### 6.2 `src/mocks/handlers.ts` — NEW

**Requirements:**
- Import `http` and `HttpResponse` from `"msw"` (MSW v2 API — not `rest`)
- Import `MOCK_PRODUCTS` from `@/data/products`
- Export a named `handlers` array
- `GET /api/products` — return `HttpResponse.json(MOCK_PRODUCTS)` (always 200)
- `GET /api/products/:id` — use the `{ id: string }` type argument on `http.get` so `params.id` is typed as `string`; find the product by string-comparing against `product.id.toString()`; return `HttpResponse.json(product)` if found; return `new HttpResponse(null, { status: 404 })` if not found

```ts
import { http, HttpResponse } from "msw";
import { MOCK_PRODUCTS } from "@/data/products";

export const handlers = [
  http.get("/api/products", () => {
    return HttpResponse.json(MOCK_PRODUCTS);
  }),

  http.get<{ id: string }>("/api/products/:id", ({ params }) => {
    const product = MOCK_PRODUCTS.find(
      (p) => p.id.toString() === params.id,
    );
    if (!product) {
      return new HttpResponse(null, { status: 404 });
    }
    return HttpResponse.json(product);
  }),
];
```

> **`http.get<{ id: string }>()`**: MSW v2's `http.get` accepts a path-params type argument. Providing `{ id: string }` types `params.id` as `string` directly — no cast needed and no `string | readonly string[]` ambiguity.

### 6.4 `src/api/products.ts` — NEW

**Requirements:**
- Import `Product` type from `@/types/product`
- Export `fetchProducts(): Promise<Product[]>` — fetches `/api/products`, throws on non-ok response
- Export `fetchProduct(id: string): Promise<Product>` — fetches `/api/products/${id}`, throws on non-ok response
- The function's declared return type (`Promise<Product[]>` / `Promise<Product>`) is the typing mechanism — `res.json()` returns `Promise<any>`, which TypeScript absorbs into the annotated return type with no error
- If the project's ESLint config uses TypeScript-aware rules (`@typescript-eslint/no-unsafe-return`), it may flag the bare `res.json()`. The fix: `return (await res.json()) as Product[]` / `as Product` — cast the awaited value instead

```ts
import type { Product } from "@/types/product";

export async function fetchProducts(): Promise<Product[]> {
  const res = await fetch("/api/products");
  if (!res.ok) throw new Error("Failed to fetch products");
  return res.json();
}

export async function fetchProduct(id: string): Promise<Product> {
  const res = await fetch(`/api/products/${id}`);
  if (!res.ok) throw new Error(`Product ${id} not found`);
  return res.json();
}
```

> **`id` is a `string`.** `useParams` always returns strings. The fetcher accepts a string and passes it to the URL. The MSW handler compares it to `product.id.toString()`. No conversion to number is needed at the API layer — keep the fetch boundary string-native.

### 6.5 `src/main.tsx` — UPDATED

**Requirements:**
- Import `QueryClient` and `QueryClientProvider` from `"@tanstack/react-query"`
- Create `queryClient` with `defaultOptions.queries.staleTime` set to 5 minutes (`1000 * 60 * 5`)
- Define an `async function enableMocking()` that conditionally imports and starts the MSW worker; it returns `undefined` in production (early return)
- Guard MSW startup with `import.meta.env.DEV`
- Use `onUnhandledRequest: "bypass"` to silence MSW warnings about Vite's own internal HMR and asset requests
- Call `enableMocking().then(...)` and do the `createRoot().render()` inside the callback — this delays rendering until the service worker is registered, preventing a race where `fetch()` fires before MSW is active
- Wrap `<App />` in `<QueryClientProvider client={queryClient}>`; place it outside `<BrowserRouter>` (data layer wraps routing layer)

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./index.css";
import App from "@/App.tsx";
import { BrowserRouter } from "react-router-dom";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5,
    },
  },
});

async function enableMocking() {
  if (!import.meta.env.DEV) return;
  const { worker } = await import("@/mocks/browser");
  return worker.start({ onUnhandledRequest: "bypass" });
}

enableMocking().then(() => {
  createRoot(document.getElementById("root")!).render(
    <StrictMode>
      <QueryClientProvider client={queryClient}>
        <BrowserRouter>
          <App />
        </BrowserRouter>
      </QueryClientProvider>
    </StrictMode>,
  );
});
```

> **`staleTime: 1000 * 60 * 5`**: Data is considered fresh for 5 minutes. Navigate Home → ProductDetail → Home within that window and no second `GET /api/products` fires. Open the Network tab, filter by Fetch/XHR, and observe this directly — the second Home visit is cache-served.

> **`import.meta.env.DEV` guard**: The MSW import is inside `enableMocking`, not at the module top level. In production, the function returns early before the dynamic import. Production bundles do not include the service worker code.

```tsx
import { useNavigate, useParams } from "react-router-dom";
import { useQuery } from "@tanstack/react-query";
import { fetchProduct } from "@/api/products";

const categoryBadgeClasses: Record<string, string> = {
  Electronics: "bg-blue-100 text-blue-700",
  Clothing: "bg-purple-100 text-purple-700",
  Books: "bg-amber-100 text-amber-700",

export default function ProductDetail() {

  const { data: product, isPending, isError } = useQuery({
    queryKey: ["product", id],
    queryFn: () => fetchProduct(id!),

    return (
      <div className="max-w-5xl mx-auto px-4 py-8">
        <p className="text-gray-500">Loading…</p>

          onClick={() => navigate("/")}

        >
          ← Back to products
        </button>
      </div>
    );
  }

  return (
    <div className="max-w-5xl mx-auto px-4 py-8">
      <button
        onClick={() => navigate("/")}
        className="text-sm text-gray-500 hover:text-gray-900 flex items-center gap-1 mb-6"

            disabled
          >
            Add to Cart
          </button>
        </div>
      </div>
    </div>
  );
}
```

> **Why `id!` in `queryFn`?** `useParams<{ id: string }>()` returns `{ id: string | undefined }` in TypeScript's view — the component might theoretically render outside a `/products/:id` route. Inside that route `id` is always defined, but TypeScript cannot infer this. The non-null assertion is safe here. The alternative — an `if (!id) return` guard before `useQuery` — would violate the Rules of Hooks (hooks cannot follow a conditional return).

## 8. Concepts Learned

| Concept | Where it appears | Why it matters |
| --- | --- | --- |
| `QueryClient` + `QueryClientProvider` | `main.tsx` | Provides the query cache to the entire component tree — must be an ancestor of every `useQuery` call |
| `useQuery({ queryKey, queryFn })` | `Home.tsx`, `ProductDetail.tsx` | The primary hook — manages fetch lifecycle, caching, and async state in one call |
| `isPending` vs `isLoading` (v5) | Both pages | `isPending` = "no cached data and currently fetching"; `isLoading` in v5 = `isPending && isFetching`, which is false for a disabled query — always use `isPending` for the initial load guard |
| `queryKey` arrays | Both pages | The cache key — `["products"]` caches the list; `["product", id]` gives each product its own cache entry |
| `staleTime` | `main.tsx` | How long data is considered fresh; during that window, revisiting a page uses cached data without re-fetching |
| `retry: false` | `ProductDetail.tsx` | Prevents TanStack Query from retrying 404 errors 3 times; surfaces the error state immediately |
| `http.get<PathParams>()` (MSW v2) | `handlers.ts` | The type argument types `params` — use it to avoid `string \| readonly string[]` ambiguity on path parameters |
| `HttpResponse` (MSW v2) | `handlers.ts` | v2 replaced the `ctx` argument API; `HttpResponse.json()` and `new HttpResponse(null, { status })` are the v2 response constructors |
| `setupWorker` from `msw/browser` | `browser.ts` | Browser-specific subpath — separate from `msw/node` used in test environments |
| `enableMocking().then(render)` | `main.tsx` | Delays React rendering until MSW is active — prevents a race where a `fetch()` fires before the service worker is registered |
| `import.meta.env.DEV` guard | `main.tsx` | MSW is dev-only — the dynamic import inside `enableMocking` is never bundled into production |
| `onUnhandledRequest: "bypass"` | `main.tsx` | Silences MSW warnings about Vite's internal HMR and asset requests that MSW should not intercept |
